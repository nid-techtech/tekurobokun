# Phase 4 修正記録

## 261114073056 バックエンドPCでcheckのBiomeが全ファイルの整形で失敗する

- 問題: バックエンドPC（Windows 11）にクローンしたリポジトリで`bun run check`を実行すると、Biomeが`package.json`・`tokens.css`・`scripts/*.ts`など、ほぼすべてのファイルを整形エラー（`line=1,col=2`）にした
- 原因: Git for Windowsの既定（`core.autocrlf=true`、システムのgitconfig）で、クローン時に作業ツリーがCRLFで書き出される。Biomeは改行をLFとして整形するため、すべての行が差分になる。開発機は同じ設定だが、ファイルをLFのまま作ってきたため表に出なかった（リポジトリの中身はLF）
- 修正: `.gitattributes`を足し、`* text=auto eol=lf`で作業ツリーの改行をLFに固定した（`*.bat`・`*.cmd`だけはCRLF）。リポジトリの中身は変わらない。`.gitattributes`より前にクローンした作業ツリーは、取り込んだあとに書き出し直す（`git rm -r --cached -q .`のあと`git reset --hard`）。手順を`CONTRIBUTING.md`の「セットアップ」に書いた。autocrlf=trueでクローンし直した作業ツリーで、LFになることを確かめた
