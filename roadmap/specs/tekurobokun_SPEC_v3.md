# tekurobokun スペックシート（展示版）

TECH☆TECHのマスコット「テクロボくん」を、ローカルLLMで会話できるロボットにする。本書は、2026年11月14日のメイカーズイベントで展示する最初の版を対象とする。

前身の`nid-techtech/tekurobokun-lite`（ヘボコン版）のコードを機体側に引き継ぐ。ヘボコン版の仕様は`tekurobo_hebocon_spec_rev4.md`（旧リポジトリの`assets/`）、全体構想は`docs/reference/tekurobo_full_vision_spec.md`を参照する。

---

## 1. 目的と想定用途

- 展示ブースで、来場者がタブレットに話しかけると、テクロボくんが人格を持って返事をする。返事は機体の声・表情・口パク・字幕で表す
- 来場者が自分で使える。混雑時や声が通らないときは、スタッフが手持ちのスマホで代わりに入力する
- 会話ログを残し、後の改善（人格のファインチューニング用データ）に使う
- 今後の拡張（レジ・接客、ゲーム、配信）の土台になる、入力元とモードを差し替えられる構成にする

## 2. 機能要件

### 会話（バックエンド）

- テキストを受け取ると、ローカルLLMに人格プロンプトと直近の会話を渡し、`{say, emotion}`形式の返事を得られる
- `emotion`は`neutral`・`happy`・`surprised`・`curious`・`troubled`の5種類から選ばせる。形式が崩れた返事や範囲外の値は、本文を`say`、感情を`neutral`として扱える（S02c）
- 考えた時間を測り、返事と一緒に入力ページへ送れる
- 返事の本文を文単位に分け、1文目の再生中に2文目を合成するように、VOICEVOXで順に音声にして機体へ送れる
- 入力と返事の両方を禁止語リストで検査し、引っかかった場合は定型の返事に差し替えられる。入力が引っかかった場合はLLMに渡さない
- 考え中・話し中の間は新しい入力を受け付けない（S01c・S01d）
- 会話をログとして保存できる（日時、入力元の端末、入力、考えた時間（LLMへの問い合わせから返事を得るまで）、LLMの生の出力、採用した`say`と`emotion`、禁止語での差し替えの有無）
- 入力を受け付ける端末を1台だけ有効にでき、バックエンドPCのターミナルでのキー入力で切り替えられる。機体と入力ページには切り替えの操作を置かない（S01g）
- LLM・VOICEVOXのどちらかが応答しないとき、機体と入力ページにその状態を伝えられる。表示はバックエンドにつながらないときと同じで、入力ページはS01f、機体はS02eとする
- 話し中に機体が切断したときは、すぐ待機中に戻る。機体から再生終了が届かないときは、送った音声の長さに余裕を足した時間で待機中に戻る

### 入力ページ（タブレット・スマホ）

- 入力欄に話した言葉（OSキーボードの音声入力）や手入力の文字を入れられる。来場者用の端末はLenovo Xiaoxin Pad（Android）で、キーボードはMicrosoft SwiftKeyのディクテーションを使う。SwiftKeyのディクテーションはネットなしで動くことを確認済み（S01a）
- キーボードは画面下に出したままにし、その上に状態行・ログ・入力行だけを置く。マイクの案内は入力欄の空欄表示に入れる（S01a〜S01e）
- 画面は、キーボードを除いて実際に見えている範囲（`visualViewport`）に収め、ブラウザがページをずらした分も打ち消す。それでも残るずれは、設定の下部マージンで調節する（S01a〜S01g）
- 入力ページはPWAとして端末にインストールし、アドレスバーを出さない全画面で起動する。PWAとして起動していないときは、最初のタップで全画面表示にする
- 入力が止まって一定時間（初期値3秒、設定で変更可）たつと自動で送信される。送るボタンでも送れる（S01b）
- 会話ログをシェル（bash・zsh）の画面のように表示する。来場者の発言は時刻つきのプロンプト行、テクロボくんの返事は「考えた時間」の行と「>」で始まる行で出す。ログは消さず、新しい行が下に追加される（S01b〜S01e）
- 入力欄はログの最後のプロンプト行として出す。考え中・話し中はプロンプトを出さない（S01c・S01d）
- 状態（待機中・入力中・考え中・話し中・つながっていません）を表示できる（S01a〜S01f）
- 考え中は、ログの末尾に「is thinking」の行を出し、点字のスピナーで示す（S01c）
- バックエンドにつながらないときは S01f、別の端末が有効なときは S01g を表示し、状況が戻れば自動で元の表示に戻る
- 端末ごとに名前を持ち（例：`tablet`、`phone`）、バックエンドは名前で有効な端末を見分けられる

### 機体（フェイシャル・音声）

- 待機中にまばたき・きょろきょろをする。間隔は疑似乱数でむらを持たせ、パラメータは設定ファイルで調整できる（S02a・S02d）
- 考え中は内側の円が回る`LOADING`表示になる（S02d）
- 受け取った音声を再生し、出力の振幅に合わせて口の高さが伸び縮みする（S02b）
- 返事の`emotion`に応じて目の形を切り替える（S02c）
- バックエンドにつながらないときは眠っている顔（目を閉じ、口を少し開け、ゆっくり上下に揺れる）になり、つながれば自動で戻る（S02e）
- 画面左上に、考え中は来場者の発言、話し中はテクロボくんの発言を1行の字幕で出せる。1行に入らない長さは末尾側を表示する（S02f）
- `f`キーでフルスクリーン、`/`キーでデバッグHUDを切り替えられる（ヘボコン版から継承）

## 3. 非機能要件

- **ネットワーク**：機体・バックエンドPC・入力端末を、持ち込みのルーターによるLANだけで動かす。インターネット接続を前提にしない（フォントも同梱する）
- **軽さ**：機体（Core m7-7Y25）では描画とWebSocketの受信だけを行う。表情が変わらない間は描画頻度を下げ、数時間の連続稼働でメモリが増え続けないこと
- **復旧**：どの機器が再起動しても、再接続は自動で行われる。機体は切断中も眠っている顔で動き続ける
- **安全**：走行はこの版では使わない。機体アプリはモーターへのコマンドを送らない
- **プライバシー**：来場者の発言はバックエンドPCにだけ保存し、外部に送らない。会話を記録していることはブースに掲示する（README に注意事項として書く）
- **国際化**：国際化の基盤を持つ。対応言語のモードは1（初版は日本語のみ）、原文は日本語。入力ページと機体の字幕の文字列は辞書から参照する
- **設定**：モデルの接続先、VOICEVOXの話者、自動送信の待ち時間、入力ページの文字の大きさ（初期値18px）と下部マージン（初期値0px）、プロンプトの表示（ユーザー名・ホスト名・ディレクトリ名。ディレクトリ名はイベントごとに変える）、人格プロンプト、禁止語リストと定型の返事、端末の一覧、アイドル動作と口パクのパラメータを、コードではなく設定ファイルで変えられる

## 4. 技術スタック

| 区分 | 採用 | 理由・確認した事実 |
|---|---|---|
| 機体アプリ | Tauri 2 ＋ TypeScript ＋ Vite、p5.js 2系（現行安定版2.3.3） | ヘボコン版の構成をそのまま引き継ぐ |
| バックエンド | Bun（1.4系）、`Bun.serve`のHTTP＋WebSocket | 機体と同じTypeScriptで型を共有できる。BunはWindows・Linuxの両方に対応 |
| LLM実行 | llama.cpp の llama-server（Vulkanバックエンド、v0.7.0以降） | OpenAI互換API。RX480（Polaris）はROCmの対象外のためVulkanを使う。UbuntuのVulkanドライバーでの動作は着手時に確認する |
| モデル | Qwen3-4B（4bit）。予備は Gemma 4 E2B（4bit） | いずれもApache-2.0。Qwen3は思考出力を無効にして使う。開発機での比較（Gemma 4 E4Bは遅く、返事の形式が崩れる）で決めた |
| 音声合成 | VOICEVOX ENGINE 0.25.2（Linux CPU版、ポート50021） | `/audio_query`→`/synthesis`でWAVを得る。GPUはLLMに使うためCPUで動かす |
| 入力ページ | 素のTypeScript ＋ Vite | 既定（Vue・SvelteKit・Astro）から外す。1画面だけで、機体アプリと書き方と型を共有できるため |
| i18n | Paraglide JS 2（Viteプラグイン） | 素のTypeScriptに対応し、キーと引数の型チェック、`Intl.PluralRules`による複数形がある。言語切り替えは`reload: false`で自前で再描画する |
| フォント | M PLUS 1 Code（入力ページ全体）、DotGothic16（機体の字幕）。いずれもSIL Open Font License | 入力ページは等幅で端末らしさを出す。オフラインで使うためファイルを同梱する |

LLMの出力形式は、llama.cppのJSONスキーマ制約がOpenAI互換のチャットAPIで使えるかを着手時に確認する。使えない場合でも、受け取ったJSONを検証して崩れを吸収する（2節）ので、機能要件は変わらない。

## 5. アーキテクチャ概要

### 構成

- **機体（Windows、Core m7）**：`apps/robot`。表示と音声再生だけを持つ薄いクライアント
- **バックエンドPC（Ubuntu、Ryzen 5 3500・32GB・RX480）**：`apps/backend`が全体の制御を持ち、llama-server（GPU）とVOICEVOX ENGINE（CPU）を呼ぶ。入力ページ`apps/console`の配信も行う
- **入力端末**：ブラウザで入力ページを開くだけ
- **通信**：機体と入力端末は、バックエンドとWebSocketでつながる。メッセージの型と取り決めは`packages/protocol`に1か所でまとめ、3つのアプリが共有する

### 会話の流れ

1. 有効な端末が`utterance`を送る
2. バックエンドが禁止語を検査し、状態を「考え中」にして全員に知らせる
3. LLMの返事を検証して`{say, emotion}`にし、禁止語を検査する
4. 文単位で音声を合成し、`emotion`・字幕の文字列・WAVを機体へ順に送る。状態は「話し中」
5. 機体が最後の文の再生終了を伝えたら「待機中」に戻る

### 責務の分割（主なもの）

| モジュール | 責務 |
|---|---|
| `ConversationSession`（backend） | 会話の状態（待機中・考え中・話し中）、直近の履歴、入力の受付可否 |
| `DialogueEngine`（backend） | LLMへの問い合わせと返事の検証。OpenAI互換のエンドポイントに依存し、モデルの差し替えは設定だけで済む |
| `TtsEngine`（backend） | 文の分割と音声合成。VOICEVOXはこの実装の1つ |
| `ContentFilter`（backend） | 禁止語の検査と定型の返事への差し替え |
| `InputDeviceRegistry`（backend） | 端末の一覧と、有効な端末1台の管理 |
| `ConversationLog`（backend） | 1行1件のJSONでの保存 |
| `FacialEngine`（robot） | 表示状態（`IDLE`・`SPEAKING`・`LOADING`・`SLEEP`）と`emotion`を受け取って描くだけ |
| `AudioPlayer`（robot） | WAVの再生と振幅の解析。口パクの値を`FacialEngine`へ渡す |
| `CaptionOverlay`（robot） | 字幕の1行表示。`FacialEngine`とは独立した重ね描き |
| `RobotLink`（robot） | バックエンドとのWebSocket接続と自動再接続 |

将来の音声認識やレジ操作は、入力元とモードの追加として`ConversationSession`の外側に足せるようにする（全体構想4節の`SpeechRecognizer`・`ModePipeline`）。ヘボコン版の`DriveStateMachine`と`SerialLink`はコードとして残すが、この版では配線しない。

## 6. デザインシステム

同梱するデザインアセット：`tekurobokun_mock.html`、`tekurobokun_tokens.css`、`tekurobokun_brand.md`、`tekurobokun_icon_master.svg`、`tekurobokun_system_const.html`（システム構成の概略図）

### モックとの差分

- 端末の切り替えは、バックエンドPCのターミナルでだけ行う。機体の無線キーボードでは切り替えない（S01gの注記の「無線キーボード」は適用しない）
- LLM・VOICEVOXのどちらかが応答しないときも、入力ページはS01f、機体はS02eを表示する（モックには描かれていない状況）

### 既知の制約

- マスターSVGは、16pxに縮小すると目と口が判別できない（32pxでは判別できる）。この版では小さいサイズ用の版を作らず、マスターSVGから展開する
- マスターSVGは、`00_bg`などの`id`を付けたレイヤー構成になっていない。この版はApple環境を対象にしないため、そのまま使う。次にclaude.aiへ差し戻すときに直す
- 入力ページはHTTPのまま配信するため、PWAのインストールには、端末のEdgeのflags（Insecure origins treated as secure）にバックエンドのオリジン（IPとポート）を登録する必要がある。オリジンが変わると、登録とインストールをやり直す

### 原則

- 入力ページはシェル（bash・zsh）の見せ方にする（反転した状態行、時刻つきのプロンプト行、「>」で始まる返事、括弧のボタン、文字の進捗バー）。文字の大きさと太さはそろえ、角丸や塗りつぶしの部品は使わない
- 入力ページの基準は横向き1280×800（16:10）。画面下約340pxをSwiftKeyのキーボードが覆う前提で配置する
- 文字は1〜2m離れても読める大きさにし、本文と背景のコントラストはWCAG AA以上
- 押せる部品は最小48×48px。キーボード操作時のフォーカスを見えるようにする
- `prefers-reduced-motion`ではカーソルの点滅や回転を止める
- フェイシャルは800×600固定で、テーマに関係なく白地黒線。目・口の基本座標はヘボコン版の`config.default.json`の値を使う

### コンポーネント方針

- 状態表示（待機中・入力中・考え中・話し中・つながっていません）
- ログの行（来場者のプロンプト行、テクロボくんの「考えた時間」の行と「>」の返事、考え中の行、`#`の案内）
- 入力欄＝最後のプロンプト行（空・入力中、考え中と話し中は出さない）
- ボタン（送る・消す。通常・hover・押下・無効）
- 自動送信の残り時間表示（文字の進捗バー）
- 全面の案内（つながらない・別の端末が有効）

### 確定事項と委任事項

- **確定事項**：トークンの値、画面構成（画面ID、各画面の要素と配置、状態、どこに何の文言があるか）、シェル風のログの行の形式、フェイシャルの描き分け、マスターSVGとアイコンの余白ルール（輪郭の外側にキャンバスの6.25%を空ける）
- **委任事項**：コンポーネントの分割と実装方式、SwiftKeyの画面（モックでは見た目の目安として描いたもの）との重なりの調整（`visualViewport`と設定の下部マージンで合わせる）、トークンの適用方法、文言の言い回しと辞書のキー設計、アイコンの各形式への展開、アイドル動作と口パクの具体的な数値

## 7. 配布・公開方法

- 一般公開はしない。各PCでリポジトリから準備して起動する
- 機体アプリは`tauri build`でWindows用の実行ファイルを作る。コード署名はしない
- 入力ページは、バックエンドが配信するものを、展示用のタブレット（Edge）にPWAとしてインストールする。HTTPSにはせず、Edgeのflagsで安全なオリジンとして扱わせる
- バックエンドPCでは、llama-server・VOICEVOX ENGINE・`apps/backend`を自動起動にする（Ubuntu）
- バージョンはSemVerで、初回は`0.1.0`

## 8. スコープ外

- 音声認識（マイク収音）とカメラ入力
- 走行・首振り（パン・チルト）などの機体の動作
- テクロボくんから話しかける動作
- 複数の感情が混ざる場合の表現
- ゲームのプレイ、配信、レジ・接客のモード
- 人格のファインチューニング、ツール呼び出し、MCP
- 英語・中国語（簡体字）への対応（後の版で追加する予定）

## 9. 未決定項目

| 項目 | 選択肢とトレードオフ |
|---|---|
| 応答時間の目標 | 送信から発話開始までの目標秒数。モデルと音声合成の実測後に決める |
| VOICEVOXの話者 | キャラクターごとに声の印象とクレジット表記の規約が違う。決めたら掲示物に「VOICEVOX:キャラクター名」を入れる |
| 人格プロンプトの中身 | 全体構想の人格設定を土台に、開発者が書く。短いほど小さいモデルでも守られやすい |
| 禁止語リストと定型の返事 | 広く取ると普通の会話まで弾く。狭いと抜けが出る |
| 実機の表示サイズと文字の大きさ | モックは1280×800（CSSピクセル）、文字18pxで描いた。実機のブラウザでの表示サイズとキーボードの高さを測り、見える行数で文字の大きさを決める |
| 会話ログの保存期間と掲示の文言 | 長く残すほど学習データになるが、来場者の発言を抱える期間も長くなる |
