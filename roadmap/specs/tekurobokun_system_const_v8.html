テクロボくん システム構成（v7）

会場には機体とconsoleだけを置き、考える処理と声を作る処理は自宅のバックエンドPCに置く。会場と自宅は、Cloudflare Tunnel（tekurobo.nid-techtech.com）を通したHTTPS・WebSocketでつなぐ。音声認識はバックエンドPCの whisper-server（LLMと同じGPU）で行い、来場者の声は外に出さない。外部のサービスは検索のTavilyだけ。

会話1回の流れ

  1. 機体のマイクの音声を、無音で区切って1発話ずつバックエンドへ送る（WSS）。テクロボくんが話している間はマイクを止める
  2. SpeechRecognizer が whisper-server で文字にする。決まり文句（「ご視聴ありがとうございました」など）だけなら捨てて待機に戻る。禁止語を検査し、全員に「考え中」を知らせる
  3. DialogueEngine が llama-server に人格・履歴を送り、{say, emotion, search} を受け取る
  4. search があれば、say（「ちょっと調べてみるね」など）を先に話し、その間に WebSearcher が Tavily で検索して、結果を付けてもう一度③
  5. TtsEngine が返事を文に分け、1文ずつ VOICEVOX で WAV にする
  6. 機体へ表情・字幕・WAVを文ごとに、console へログの行を送る。状態は「話し中」
  7. 機体が最後の文の再生終了を返すと「待機中」に戻り、マイクを開く

つなぎ方の決まりごと

  • 会場と自宅は Cloudflare の名前付きトンネルだけでつなぐ。自宅のルーターのポートは開けない
  • 機体と console は、登録コード（ランチャーに出る、短命・1回限り）をトークンと交換して接続する。機体はQRをカメラで、console は文字で入れる
  • 管理用API（登録コードの発行、入力元の切り替え、マイクの一時停止、会話のリセット）は 127.0.0.1 だけで待ち受け、トンネルに載せない
  • llama-server の正と副は同じポートで、同時には動かさない。backend は接続先を変えずに済む
  • whisper-server は llama-server と同じ GPU（8GB）に載せる。ランチャーは LLM の読み込みが終わってから起動し、正→副の切り替えでは止めない
  • 回線や外部サービスが止まると、機体は眠っている顔、console は「つながっていません」になる
